# Stage 3: Beats

A **beat** is one move in the reader's journey: it may be a sentence or several paragraphs, whatever that move naturally is. Beats follow the outline; the outline follows the argument.

## Grounding

A beat may only lean on concepts the reader already has: those listed as grounded in the Brief, or introduced by an earlier beat. Leaning on an ungrounded concept loses the reader, even with no jargon in sight. When a beat introduces a concept, land the idea and its name together, then add it to `## Grounded concepts` in the Brief.

The prerequisites decision is the big lever: assume too much and you lose readers; assume too little and early beats drown in definitions. Settled in the Brief, revisited if the user hesitates.

## Offering beats

At each step offer 2-3 candidates:

```markdown
**A. Start with the pain** — the 10th time re-explaining the repo to an agent. Grounds: *session reset*. Uses C2 (F08, F10).
**B. Start with the answer** — state C1 outright, then show why. Grounds: *session reset*, *vault*. Uses C1.
**C. Start with the objection** — "won't bigger context windows fix this?" Requires: *context window* (grounded). Uses C4.
```

Say what each grounds and which ledger rows it uses, so the user sees which paths it opens. All must be reachable from the current grounded set.

## Writing a beat

- Write only the chosen beat, then stop and re-read the file from disk.
- Mine fragments; don't paste them. Split, merge, paraphrase into one voice.
- Cite inline at the claim: `…the context resets every session ([[Context Windows Reset Per Session]]).`
- Hedge to the ledger strength (see CLAIM-LEDGER.md). Never upgrade.
- Pull from the pile first. If the beat needs something the pile lacks, say so: "This beat needs an example and the pile has none: give me one, research it, or we cut it."

## Format choices to discuss, not make silently

- Prose for argument; lists only for genuinely parallel items.
- Table when the same shape repeats 3+ times.
- Quote when the wording is the point, paraphrase when only the idea is.
- Callouts (`> [!NOTE]`) only for asides that would derail the main line.

## Out of scope

Editing the source notes (except linking the draft from them), adding platform frontmatter, publishing.
