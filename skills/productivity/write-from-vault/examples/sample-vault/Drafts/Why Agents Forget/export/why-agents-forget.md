# Why Coding Agents Forget Your Project

Your coding agent forgets your project because every session starts empty, and the fix is to give it somewhere to write things down: a vault of small, linked notes it reads when it starts[^1][^2].

## Every session starts from zero

Whatever the agent worked out yesterday is gone today unless it lives in a file loaded at startup[^1]. In my interviews with developers who use agents daily, re-explaining the project was the most common frustration, named by 9 of 12[^3].

## Notes the agent reads back

When research and decisions land as short linked notes with an index the agent reads first, the next session picks up where the last one stopped. That has held across three months of my own projects[^2].

## What about bigger context windows?

I expect longer context to help less than it seems: a bigger window holds more, but someone still has to choose which past decisions matter. That is a hunch from my own testing, not a measured result[^4].

Start small: next time your agent figures something out, have it write a note.
